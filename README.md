# PUBG Name Lab

An independent PUBG Mobile nickname toolkit: <https://pubg-name-lab.vercel.app/>. Not affiliated with PUBG MOBILE, Tencent or KRAFTON.

## Pages
| Page | What it does |
|---|---|
| `index.html` | Type a name, copy styled variants. Discover strip and collection tiles. |
| `discover.html` | Theme generator: lock and reroll parts, optional frames, length limit, keep-my-word. |
| `names.html` | Curated collection (156 names, 10 categories) with search, filter, sort. |
| `studio.html` | Part-by-part builder: per-part styles, frames, prefix/suffix, undo/redo, symbol picker. |
| `inspect.html` | Unicode inspector: code points, names, scripts, UTF-8/16, normalisation, warnings, lookalike compare. |
| `library.html` | 2,700+ characters, searchable by word, glyph, code point or Unicode name. Includes blank/invisible characters with warnings. |
| `compatibility.html` | Evidence ladder, official rules and gaps, test lab, local test log, GitHub issue submission. |
| `guide.html` | Rules, counting methods, normalisation, checklist, sources. |
| `mynames.html` | Saved names (browser only), export/import, in-game test buttons. |

No build step is needed to run the site. It is plain HTML, CSS and classic scripts.

## Editing pages
Page bodies live in `tools/pages/*.html`. After editing one (or the shared header/footer in `tools/build-pages.py`):

    python3 tools/build-pages.py

This regenerates the root `.html` pages and `sitemap.xml`. Commit the generated files.

## Data files
- `js/names-data.js`: curated names as `[base, style, frame]`. A base starting with `=` is literal.
- `js/words-data.js`: word banks per Discover theme.
- `js/library-data.js`: character groups.
- `data/unicode-names.js`, `data/unicode-blocks.js`: generated by `tools/build-unicode-data.py` (needs `fonttools`). Unicode 15.1.

## Length counting
PUBG MOBILE has not published a nickname length limit or counting method. Players quote 14. One report: a name with 11 visible characters (`CīOīLīLīIīN`) but 16 UTF-8 bytes was called too long, which suggests bytes are counted. The site shows all four counts and the generator defaults to the strictest. The Compatibility page has a "Length counting" test pack to settle it.

## Compatibility evidence
Four levels: Valid Unicode, Community-reported, Verified, Officially documented. `PNL.COMPAT.records` in `js/compat.js` starts **empty**: nothing is claimed as tested until someone records it.

Users' own results are saved in their browser (shown as "You") and can be sent as a GitHub issue. To publish one, check the evidence, then add a record:

    { text: 'Nl★x7', target: '★', result: 'ok', game: '4.1.0', platform: 'Android', device: 'Galaxy S23',
      tested: '2026-11-24', source: 'community', verified: false, evidence: 'https://…', note: '' }

Set `verified: true` only after reproducing it or receiving two independent reports with screenshots.

## Hosting
Static site on Vercel (`vercel.json` sets headers and a Content-Security-Policy). Keep `google…html` and `yandex…html` at the root for search-console verification.
